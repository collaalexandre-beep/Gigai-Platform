Criar uma nova tela chamada:

**Central de Suprimentos**

Ela deve funcionar como uma tela de atenção operacional, e não como dashboard fixo.

Criar um endpoint novo:

`GET /api/supplies/attention`

Esse endpoint deve retornar uma lista de itens de atenção com este formato aproximado:

```ts
{
  id: string;
  type: "urgent" | "risk" | "attention" | "opportunity" | "info";
  title: string;
  description: string;
  module: "estoque" | "compras" | "xml" | "financeiro" | "fornecedor";
  entityId?: string;
  entityType?: string;
  actionLabel?: string;
  actionUrl?: string;
  priorityScore: number;
  createdAt?: string;
}
```

Regras iniciais para gerar itens de atenção:

1. Estoque crítico:

   * Buscar materiais ativos em `rawMaterials`.
   * Se estoque atual for menor ou igual ao estoque mínimo, gerar alerta.
   * Se estoque for zero ou negativo, classificar como `urgent`.
   * Se estoque estiver abaixo do mínimo, classificar como `risk`.

2. Solicitações de compra:

   * Buscar `purchaseRequests` com status aguardando aprovação.
   * Gerar item `attention`.
   * Se a urgência for alta ou urgente, elevar para `risk`.

3. XML/NF-e:

   * Buscar `nfeImports` com status pendente.
   * Se houver itens não mapeados em `nfeImportItems`, gerar item `risk`.
   * Se XML estiver pendente mas sem divergência crítica, gerar item `attention`.
   * O objetivo é mostrar apenas o que precisa de conferência humana.

4. Contas a pagar:

   * Buscar `accountsPayable` pendentes.
   * Se vencidas, gerar `urgent`.
   * Se vencem nos próximos 3 dias, gerar `attention`.
   * Não gerar alerta apenas por existir conta a pagar futura.

5. Fornecedores:

   * Nesta fase, mostrar apenas informações básicas se houver dados relevantes já disponíveis.
   * Não criar lógica complexa de promoção ainda.
